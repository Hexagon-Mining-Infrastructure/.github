# Documentation

## Where documentation lives

| Kind | Location |
|---|---|
| How to use a module / repo | That repo's `README.md` |
| How to contribute to a repo | That repo's `CONTRIBUTING.md` (falls back to the org default here) |
| Instructions for AI agents | That repo's `AGENTS.md` / `CLAUDE.md` |
| Platform architecture, runbooks, decisions | `wiki-infra-docs` |
| Org-wide practices and repo map | This repo (`.github`) |

Don't duplicate: link to the canonical source.

## Every repository has

- `README.md` — purpose, usage example, inputs/outputs (Terraform), owners, links.
- `CHANGELOG.md` — generated by semantic-release.
- `LICENSE` and, where relevant, `UPGRADE-x.0.md` for breaking changes.
- `CODEOWNERS` — so reviews route automatically.

## Terraform READMEs

- Write the human part in `.header.md` (purpose, architecture, examples, gotchas).
- The rest is generated by `terraform-docs` from `.terraform-docs.yml` — **never hand-edit the generated section**.
- Regenerate in the same commit as any variable/output change (`pre-commit` does this; the `docs-sync` agent can help).

## Style

- Write for someone new to the team. Lead with what it is and when to use it.
- Prefer tables and runnable examples over prose.
- Use Mermaid for diagrams so they're reviewable as text.
- Use relative links within a repo; full URLs across repos.
- Update docs in the **same PR** as the change.
