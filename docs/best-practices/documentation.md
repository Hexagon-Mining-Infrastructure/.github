# Documentation

## Where documentation lives

| Kind | Location |
|---|---|
| How to use a component / repo | That repo's `README.md` |
| How to contribute to a repo | That repo's `CONTRIBUTING.md` (falls back to the org default here) |
| Platform architecture, runbooks, decisions | Internal platform documentation (members only) |
| Org-wide practices | This repo (`.github`) |

Don't duplicate: link to the canonical source.

## Every repository has

- `README.md` — purpose, usage example, inputs/outputs, owners, links.
- `CHANGELOG.md` — generated by release tooling.
- `LICENSE` and, where relevant, upgrade notes for breaking changes.
- `CODEOWNERS` — so reviews route automatically.

## Generated docs

- Write the human part by hand (purpose, architecture, examples, gotchas).
- Generated reference sections are **never hand-edited**; regenerate them in the same commit as
  any input/output change.

## Style

- Write for someone new to the team. Lead with what it is and when to use it.
- Prefer tables and runnable examples over prose.
- Use text-based diagrams so they're reviewable as text.
- Use relative links within a repo; full URLs across repos.
- Update docs in the **same PR** as the change.
