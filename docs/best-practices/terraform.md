# Terraform

## Versions

| Tool | Constraint |
|---|---|
| Terraform | `~> 1.12.2` |
| AWS provider | `~> 6.0` |
| Kubernetes provider | `~> 2.23` |
| Helm provider | `~> 2.11` |

```hcl
terraform {
  required_version = "~> 1.12.2"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}
```

- Generic `terraform-aws-*` modules may declare a wider **minimum** (`>= 1.x`) so they stay reusable;
  `terraform-hxmin-*` and `terraform-live-*` use the constraints above.
- Every module `source` from the registry has an **exact pinned `version`** — no ranges, no git refs to branches.
- Commit `.terraform.lock.hcl` in live repos.

## Standard repository layout

```text
.
├── main.tf / locals.tf      # resources and locals
├── variables.tf             # inputs, each with description + type (+ validation where useful)
├── outputs.tf               # outputs, each with description
├── versions.tf              # required_version + required_providers
├── modules/<sub-module>/    # sub-modules (HxMIN repos)
├── examples/                # runnable examples (generic modules)
├── tests/                   # terratest / terraform test
├── .header.md               # human-written README header (terraform-docs injects the rest)
├── .terraform-docs.yml  .tflint.hcl  trivy.yaml  .pre-commit-config.yaml
├── CHANGELOG.md             # generated by semantic-release
└── README.md                # generated — do not hand-edit below the header
```

Use the `tf-module-author` agent or copy an existing repo of the same layer rather than starting from scratch.

## Naming

- All Terraform identifiers are `snake_case` (enforced by tflint `terraform_naming_convention`).
- Don't repeat the resource type in its name: `aws_vpc.this` / `aws_vpc.management`, not `aws_vpc.vpc`.

### Workspaces and resource prefixes

| Component | Pattern | Example |
|---|---|---|
| Workspace | 5 consonants + 3 digits, regex `^[BCDFGHJKMNPQRSTVWXYZ]{5}[0-9]{3}$` (no vowels, no `L`) | `CSDVD001` |
| Environment symbol | `D` dev · `Q` qa · `S` staging · `T` uat · `P` production | `D` |
| Configuration ID | `{workspace}{env_symbol}` | `CSDVD001D` |
| Resource prefix | `lower(configuration ID)` | `csdvd001d` |

```hcl
locals {
  configuration_id = "${terraform.workspace}${var.environment_symbol}"
  resource_prefix  = lower(local.configuration_id)
}
```

### AWS resource names

| Resource | Pattern | Example |
|---|---|---|
| IAM role | `rol-{purpose}-{env}` | `rol-cert-manager-dev` |
| IAM policy | `pol-{purpose}-{env}` | `pol-cert-manager-dev` |
| IAM path (Terraform) | `/hxmin-cloud/cpds-shared/{env}/terraform/` | |
| IAM path (Kubernetes) | `/hxmin-cloud/cpds-shared/{env}/k8s/` | |
| S3 bucket | `s3b-{purpose}-{env}` | `s3b-tf-statestore-dev` |

## Tagging

Every taggable resource carries the common tags; callers can add more through `var.tags`.

```hcl
locals {
  common_tags = {
    Terraform   = "true"
    Environment = var.environment
    ManagedBy   = "Terraform"
    Owner       = "cpds"
    Repository  = "<repo-name>"
    Project     = "CPDS"
    Module      = "<module-name>"
    LeasePeriod = "permanent"
  }
}

# variables.tf
variable "tags" {
  description = "Additional tags merged into every resource."
  type        = map(string)
  default     = {}
}

# usage
tags = merge(var.tags, local.common_tags)
```

Prefer the provider's `default_tags` in live repos so nothing is missed.

## Writing modules

- **Variables:** always `description` and `type`; add `validation` for formats (CIDRs, names, enums).
  Mark secrets `sensitive = true`. Avoid `any`.
- **Outputs:** always `description`; expose IDs/ARNs consumers need, nothing more.
- **No provider blocks** in reusable modules — providers are configured in live repos.
- **No hard-coded** account IDs, regions, ARNs or CIDRs; derive them (`data.aws_caller_identity`, variables).
- Prefer `for_each` over `count` for anything with identity.
- Use `moved {}` blocks when renaming or restructuring, so consumers don't destroy/recreate.
- Keep secure defaults on: encryption at rest, IMDSv2, private subnets, blocked public S3 access.

## Live repositories

- One workspace = one directory/config, validated by the `workspace-validator` rules in CI.
- Remote state with locking; never commit state or `*.tfvars` containing secrets.
- Every PR shows a `terraform plan`; reviewers read it, not just the diff.
- `apply` runs only from CI after merge — no local applies to shared environments.
- Promote through environments in order: dev → qa → staging → uat → production.
- Decommission workspaces with the `workspace-cleanup` action, not by deleting directories.

## Releases

- Modules are released by `semantic-release` from Conventional Commits; never tag by hand.
- Breaking changes require a major bump and an `UPGRADE-x.0.md` with migration steps.
- After a release, bump the version in the consuming layer in a separate PR.

## Local checks

```bash
pre-commit install            # once per clone
pre-commit run --all-files    # fmt, validate, tflint, trivy, terraform-docs, secret scan
```

The `terraform-preflight` agent runs the full suite and explains failures.
